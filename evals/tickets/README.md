# Eval tickets

Helpdesk tickets with one planted root cause each, and their answer keys. Generated by `make tickets` (`app/mock/tickets.py`) from the cause catalog in `app/mock/faults.py`; a test fails if these files drift from the generator.

| File | Issues | Tickets | Use |
| --- | --- | --- | --- |
| `tuning.jsonl` | 3 (printer, disk space, app updates) | 18 with a cause + 2 to escalate | Free to use while building |
| `heldout.jsonl` | the other 10 | 92 with a cause + 8 to escalate | **Never used for tuning.** Scored once per change |

## How a ticket works

- `issue`, `employee_id`, `subject`, `message`: what the copilot sees. Messages describe symptoms only and never name the cause.
- `answer`: the key. `cause` (a cause id, or `escalate`), `outcome` (`fix` or `escalate`), `requires_approval` (the fix changes an account), `reveals` (the checks whose answer differs from a healthy world), `fix`.
- `tickets.world_for(ticket)` rebuilds the company the copilot will find: the healthy fixture with that one cause planted. Serve it to the mock systems with `MOCK_COMPANY`.

## Design

- 36 causes across 13 issues, 2 to 4 each. Some are deliberate misdirection: a VPN ticket caused by a locked account, an antivirus ticket caused by an expired VPN certificate, an MFA ticket caused by an SSO outage.
- Escalation tickets plant nothing: every check is healthy, so the right answer is to escalate with the evidence, not to guess.
- The split is by issue, so no held-out issue was seen while tuning.
- A test plants every cause and checks that exactly the listed checks change, so `reveals` is verified, not assumed.

## Rules

These files are eval ground truth (`AGENTS.md`). Change the causes, templates or tickets only in their own pull request, never together with agent code.
